# eyetracking_analytics

> На английском: [`README.md`](README.md)

Библиотека разметки и анализа **движений глаза и взора**: выделение переводов
взора, фиксаций и интегральных характеристик записи по авторским методикам.
Методика расчета пороговых значений 
опирается на модель главной последовательности саккад с учетом частоты съема.

При использовании библиотеки в исследованиях **просьба ссылайтесь на статью**, результат
которой заложен в расчёт порогов — см. [Как ссылаться](#как-ссылаться).

> Область применимости — данные глаза и взора.

## Принаджность понятий

Определяет всю терминологию API:

| Понятие | Описание| Связанное событие                         |
|---|------------------------------------------------------|-------------------------------------------|
| **Движение глаза** | движение глаза относительно черепа                   | **саккада**                               |
| **Взор** | рассчитывается относительно окружающего пространства | **(быстрый) перевод взора**, **фиксация** |

В разметке взора относительно быстрое движение называется переводом взора, а не саккадой:
в изменение взора входит и движение головы. Параметры взора могут совпадать
с параметрами для глаза только в случае монокулярного окулографа и неподвижной
головы. Модели саккады не применима к обзему случаю перевода взора. 

**Различение по системе координат.** Если величина задана в координатах,
связанных с головой или с носимым окулографом/айтрекером, она относится
к **глазу** — сколько бы прибор ни называл её gaze. Взором она становится только
после учёта положения головы
в неподвижном пространстве. 

Пример, Pupil Invisible пишет один глаз, и его
`azimuth/elevation` заданы в системе камеры сцены, жёстко связанной с головой: это
движение глаза, а не взор.

Между переводами взора выделяются:

* **фиксация** — интервал между переводами взора, прошедший четыре проверки:
  скорость ниже порога, статистическая однородность (постоянство положения),
  допустимый пространственный разброс и длительность не меньше минимальной.
  Скорость для первой проверки считается как смещение за окно 10 мс
  (`fixation_velocity_window_s`), а не как разность соседних отсчётов: шум
  разности растёт с частотой записи, а порог модели с частотой падает. Интервал
  урезается до отсчётов ниже порога; `trim_fixations_by_velocity=False`
  задает поведение: интервал брется целиком;
* **интервал медленного движения** — всё, что лежит между переводами взора, без
  проверок. Для взора это корректная величина, но фиксацией она не является:
  между переводами взор может медленно смещаться.

Для собственного движения глаза фиксации нет: **фиксация — состояние взора**,
взор удерживается на объекте неподвижного пространства, и голова с глазом при
этом вполне могут двигаться, компенсируя друг друга. Неподвижность глаза
относительно черепа — это **покой**, другая величина:

| величина | функция | проверки |
|---|---|---|
| **интервал покоя** | `mark_eye_rest_from_angles` | скорость, однородность, разброс, длительность |
| **интервал между саккадами** | `mark_eye_data_with_full_angle_from_angles` | однородность, разброс, длительность |
| **устойчивый интервал** | `stable_intervals_by_velocity` | только скорость: подряд идущие отсчёты ниже порога |

## Ключевое свойство: пороги выводятся из частоты записи

Разрешающая способность записи задаёт, какую саккаду вообще можно
детектировать. Отсюда все пороги считаются моделью по фактической частоте,
а не задаются константами:

| fs, Гц | мин. амплитуда, град | мин. длительность, мс | порог пика, град/с | порог фиксации, град/с |
|---:|---:|---:|---:|---:|
| 60 | 8.55 | 50.0 | 243.6 | 171.0 |
| 90 | 1.87 | 33.3 | 94.1 | 37.4 |
| 250 | 0.25 | 18.4 | 28.2 | 5.0 |
| 1250 | 0.25 | 20.0 | 29.2 | 5.0 |

Снизу пороги ограничены физиологией: скорость идеальной фовеальной фиксации
5 град/с, её пространственный разброс 5 град, минимальная длительность 50 мс.
Без этих границ модель при высоких частотах давала пиковую скорость саккады
0.32 град/с — физически невозможное значение.

Следствие, о котором надо знать: **значения метрик сопоставимы только между
записями одной частоты** либо после приведения записей к общей частоте.

## Быстрый старт

```python
import pandas as pd
from eyetracking_analytics import markup
from eyetracking_analytics.report import enable_report_logging

enable_report_logging()          # чтобы видеть, при каких значениях всё посчитано

data = pd.read_csv("record.csv")  # столбцы: T_s (секунды!), gaze_yaw, gaze_pitch

result = markup.mark_gaze_events_direction(
    data,
    col_gaze_x="gaze_yaw",
    col_gaze_y="gaze_pitch",
    col_time="T_s",
    geometry="angles",           # yaw/pitch на единичной сфере
)

print(len(result.gaze_shifts), "переводов взора")
print(len(result.fixations), "фиксаций")
print(result.fixations[["t_start_s", "duration_s", "mean_eccentricity_deg", "spread_deg"]])
```

Пороги здесь не заданы — они выведены из частоты записи. Журнал покажет, какие
именно значения применены и откуда взято каждое:

```
[eyetracking_analytics] разметка переводов взора по направлению
  запись ............................ 19.99 с, 1800 отсчётов   (из данных)
  частота записи .................... 90 Гц   (из данных: дрожание шага 0.0 %)
  параметризация .................... angles   (пользователь: yaw/pitch на сфере)
  порог пика скорости ............... 94.1437 град/с   (модель)
  порог скорости на фиксации ........ 37.3693 град/с   (модель)
  минимальная амплитуда ............. 1.8685 град   (модель)
  найдено ........................... 14 переводов взора, 29 фиксаций   (вычислено)
```

## Требования к входным данным

1. **Отсчёты времени обязательны и в секундах.** Ось в миллисекундах
   отвергается с явным сообщением: без этой проверки ошибка проходила молча —
   скорости выходили в тысячу раз меньше порогов, и на выходе оказывалась
   не ошибка, а правдоподобная пустая таблица событий.
2. Углы — в градусах. Плоские координаты — в любых единицах, но тогда нужно
   расстояние до плоскости `r` в тех же единицах.
3. Неравномерный шаг допускается: частота оценивается по медианному шагу,
   дрожание измеряется и попадает в журнал.
4. Приведение к другой частоте — **децимация** (выбор реальных отсчётов,
   как записал бы прибор с этой частотой), без интерполяции и осреднения.
   Запросить частоту выше частоты записи нельзя.

## Состав

| Модуль | Назначение |
|---|---|
| `markup` | разметка переводов взора и фиксаций: одномерная запись и запись направления |
| `models` | модель главной последовательности саккад, все пороги по частоте |
| `sampling` | оценка частоты, проверка единиц времени, децимация |
| `for_raw_data` | сырые данные глаза: окулограмма, нейтральное положение, сглаживание, скорость |
| `eyetracking_funs` | метрики: коэффициент стабилизации взора, длина траектории, статистика интервалов |
| `gaze_mark` | препроцессинг и вычислительные ядра разметки |
| `orientation` | ориентация головы и взора: кватернионы → углы, поворот векторов |
| `blinks` | моргания: поиск по отметке качества или по сигналу, уточнение границ, маска |
| `saccade_model` | модель траектории саккады: семейство кривых и поиск похожих в записи |
| `report` | журнал вычислений: какие параметры применены и откуда взяты |

Раскладка: пакет лежит в `src/eyetracking_analytics/`, тесты — в `tests/`.

Подробное описание функций, единиц и схем таблиц — в

## Воспроизводимость

Это исследовательский код, результаты которого идут в публикации, поэтому
воспроизводимость поставлена выше удобства:

* **наличие ускорителей не влияет на разметку.** numba опциональна; её ветки
  считают тот же алгоритм, и CI гоняет весь набор по матрице {numba есть / нет} ×
  Python 3.10–3.12. Раньше две ветки реализовывали *разные* алгоритмы, и
  результат зависел от того, установлена ли numba. Совпадение при этом
  алгоритмическое, а не побитовое: ускоренная сумма идёт циклом, а numpy —
  попарно, поэтому наклон и p-value тренда расходятся в последних битах (1e-14).
  Ни одно событие, ни одна граница от этого не меняются, и эталон снимается
  на python-ветке, чтобы не зависеть от окружения;
* **поведение методики зафиксировано эталоном.** 48 фикстур на синтетических
  записях с фиксированным seed; любое изменение, меняющее числа, обязано быть
  осознанным и описанным в `CHANGELOG.md`. Сравнение двухуровневое: схема,
  границы событий и длительности — точно, непрерывные величины — с допуском
  1e-9, а в окружении, где снят эталон, дополнительно до последнего бита
  (подробнее — в [`tests/README-rus.md`](tests/README-rus.md));
* **каждый результат несёт условия своего получения** в `params_used`: их можно
  сохранить рядом с таблицами и восстановить текст отчёта через
  `report.describe(...)`;
* **схема результата не зависит от имён входных столбцов.** Внутри расчёта оси
  называются канонически (`gaze_x`, `gaze_y`), наружу — как в ваших данных
  (`columns="canonical"` оставляет канонические имена).

## Подключение к своему проекту

Библиотека закрытая и подключается к проектам автора как пакет.

```bash
pip install -e .                 # библиотека
pip install -e ".[fast]"         # + numba (ускорение, на числа не влияет)
pip install -e ".[viz]"          # + plotly, matplotlib, seaborn
pip install -e ".[dev]"          # + pytest, ruff
```

Из проекта, где библиотека лежит подмодулем:

```bash
git submodule update --init eyetracking_analytics
pip install -e ./eyetracking_analytics
```

Или прямо из репозитория, без подмодуля (нужен доступ по SSH):

```bash
pip install "git+ssh://git@github.com/ankorm/eyetracking_analytics.git@public"
pip install "git+ssh://git@github.com/ankorm/eyetracking_analytics.git@v0.2.0"  # с фиксацией версии
```

> **Важно для старых проектов.** Раньше достаточно было положить подмодуль
> в каталог проекта: модули лежали в его корне и находились по `sys.path`.
> Теперь пакет лежит в `src/`, поэтому **каталога подмодуля на пути
> недостаточно** — `from eyetracking_analytics import eyetracking_funs` даёт
> `ImportError: ... (unknown location)`. Достаточно один раз выполнить
> `pip install -e ./eyetracking_analytics`; сами импорты в блокнотах менять
> не нужно, они продолжают работать как прежде.

Публичный API перечислен в `eyetracking_analytics.__all__` — 68 имён;
всё остальное является реализационной деталью.

## Как ссылаться

Библиотека — не самостоятельный инструмент: в неё интегрирован результат
исследования. Параметры главной последовательности `(T0_ms, m, V0, n)`, из
которых выводятся все пороги детектирования, взяты из таблицы 4 статьи и
пересчитаны по частоте дискретизации. Поэтому ссылаться нужно **на статью**:

> Kruchinina A., Xu X. Analysis of saccadic main sequence relationship from
> a time-optimal control perspective // Russian Journal of Biomechanics. —
> 2026. — Vol. 30, no. 1. — P. 108–114. — DOI 10.15593/RJBiomech/2026.1.10

Это ссылка на всю разметку: пороги считаются по модели в любом сценарии
использования библиотеки.

Отдельно — **модель траектории саккады** (`saccade_model`): звено второго
порядка с релейным управлением и моментами переключения из условия попадания.
Если использовались `saccade_template`, `saccade_template_family` или
`match_saccade_templates`, добавьте:

> Kruchinina A., Yakushev A. G. Parametrization of Saccade Trajectories //
> Moscow University Mechanics Bulletin. — 2018. — Vol. 73, no. 4. — P. 97–100. —
> DOI 10.3103/S0027133018340052
>
> Kruchinina A. Optimal time task in saccadic eye movement // Russian Journal
> of Biomechanics. — 2020. — Vol. 24, no. 1. — P. 33–39. —
> DOI 10.15593/RJBiomech/2020.1.04

Ссылка на код — дополнительно к статьям, а не вместо них. Машиночитаемая форма
всех ссылок лежит в [`CITATION.cff`](CITATION.cff): статья главной
последовательности в `preferred-citation`, статьи модели траектории
в `references`. На GitHub этот файл даёт кнопку «Cite this repository»,
а DOI релиза выдаёт Zenodo.
