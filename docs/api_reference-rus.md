# Справочник API

> На английском: [`api_reference.md`](api_reference.md)

Единицы во всём публичном API: **секунды, градусы, герцы**. Отсчёты времени обязательны и задаются в секундах — ось в миллисекундах отвергается с явным сообщением.

Каждая функция сообщает в журнал, при каких значениях получен результат и откуда взят каждый параметр (`модель`, `пользователь`, `из данных`, `по умолчанию`, `вычислено`). Для вывода в блокноте:

```python
from eyetracking_analytics.report import enable_report_logging
enable_report_logging()
```

## Подготовка данных: ориентация головы и глаза (`direction`)

Первый шаг работы: запись прибора приводится к направлению взора, с которого начинается вся разметка. Прибор пишет ориентацию так, как ему удобно, а разметке нужен один вид, поэтому перевод сделан здесь, а не оставлен каждому проекту.

**Система координат** правая и фиксированная: **X** вправо, **Y** вверх, **Z** вперёд; нейтральное направление — взгляд прямо перед собой — `[0, 0, 1]`. Порядок столбцов вектора всегда `x, y, z`, кватерниона — `q_x, q_y, q_z, q_w` (скаляр последний). Кватернион означает поворот **из локальной системы в родительскую**: голова — в неподвижное пространство, глаз — в систему головы.

### Сложение поворотов головы и глаза

Взор складывается из двух ориентаций, заданных в разных системах:

* **голова** — ориентация в неподвижном пространстве: куда повёрнута голова относительно комнаты;
* **глаз** — ориентация **относительно головы**: куда отведён глаз в глазнице. Это не направление в пространстве, и само по себе оно взором не является.

Итог — композиция, в которой порядок существен: сначала применяется поворот глаза, затем поворот головы. В кватернионах это произведение `q_взор = q_голова · q_глаз`, в векторах — поворот направления глаза ориентацией головы. Обратный порядок описывал бы другое движение: глаз, вращающий голову.

Направление взора получается как поворот нейтрального направления итоговым кватернионом: `gaze = q_взор · [0, 0, 1]`.

| Что задано | Что получается | `is_gaze` |
|---|---|---|
| голова и глаз | **взор**: направление в неподвижном пространстве | `True` |
| только голова | направление головы; взор считается совпадающим с ним | `True` |
| только глаз | **движение глаза** относительно головы, а не взор: фиксацией такие интервалы называть нельзя, в журнал идёт предупреждение | `False` |

Проверка смысла на самом простом случае: если голова поворачивается на 20°, а глаз компенсирует поворот, композиция даёт неподвижный взор — эксцентриситет ниже 1e-9 и ни одного перевода взора. Та же запись без учёта глаза выглядит как уход взора на угол поворота головы. Ровно это различие и стоит за тем, что фиксация относится ко взору, а покой — к глазу.

**Допущение о торсии.** Вектор направления не задаёт поворот вокруг самого себя. Если ориентация головы задана вектором, а глаз — кватернионом, торсия головы при композиции принимается нулевой (берётся кратчайший поворот от направления вперёд), и это пишется в журнал. Кватернион и вектор поворота торсию задают — там допущения нет.

### Функции

| Функция | Что делает |
|---|---|
| `gaze_direction(head=None, eye=None, *, head_representation="quaternion", eye_representation="quaternion", head_cols=None, eye_cols=None, head_initial=None, eye_initial=None, rotation_vector_in_degrees=False) -> GazeDirection` | направление взора из ориентации головы и, если есть, глаза |
| `orientation_to_direction(data, *, representation="quaternion", cols=None, initial=None, rotation_vector_in_degrees=False)` | одна ориентация → единичный вектор `[N, 3]` |

Представления (`REPRESENTATIONS`) задаются отдельно для головы и глаза и могут не совпадать:

| Значение | Вход | Столбцов |
|---|---|---|
| `"vector"` | вектор направления | 3 |
| `"quaternion"` | кватернион ориентации | 4 |
| `"quaternion_relative"` | кватернион относительно исходной ориентации; сама она — в `*_initial` | 4 |
| `"rotation_vector"` | вектор поворота: ось — направление, угол — длина | 3 |

`GazeDirection`: `direction` (`[N, 3]`, единичные), `head_direction`, `eye_direction`, `n_samples`, `is_gaze`, `params_used`. Метод `to_frame(t_s, *, col_time="T_s", prefix="gaze")` даёт таблицу со столбцами `gaze_forward`, `gaze_right`, `gaze_up` — в порядке, которого ждёт разметка:

```python
gaze = gaze_direction(head=head_quat, eye=eye_quat)
res = mark_gaze_events_direction(
    gaze.to_frame(t_s), col_time="T_s", geometry="vector",
    col_horizontal="gaze_forward", col_vertical="gaze_right", col_forward="gaze_up")
```

## `markup` — разметка событий

Три раздельные сущности по типу записи. Термин «саккада» относится к движению глаза относительно головы; для взора событие называется **переводом взора**.

Во входных столбцах ожидается **взор**, то есть направление относительно неподвижного пространства: положение головы плюс положение глаза. Если голова считается неподвижной (подбородник, короткий интервал без движения головы), достаточно направления глаза — но это допущение о записи, а не о данных.

### `mark_gaze_events_1d(data, *, col_gaze_angle, col_time="T_s", ...) -> ScalarMarkup`

Одномерная угловая запись: окулограмма по одной оси либо готовый эксцентриситет. Скорость `|da/dt|`, амплитуда события `|Δa|`.

| Параметр | Ед. | По умолчанию | Смысл |
|---|---|---|---|
| `col_gaze_angle` | — | обязателен | столбец угловой координаты, град |
| `col_time` | — | `"T_s"` | столбец времени, с |
| `col_speed` | — | `None` | готовая угловая скорость взора, град/с; `None` = производная положения |
| `speed_smoothing_points` | отсчёты | 0 | медианный фильтр по скорости, нечётное число; 0 = без сглаживания |
| `min_peak_velocity_deg_s` | град/с | из модели | минимальная высота пика скорости |
| `fixation_velocity_limit_deg_s` | град/с | из модели | порог «скорость уже фиксационная» |
| `min_amplitude_deg` | град | из модели | минимальная амплитуда события |
| `min_event_duration_s` | с | 0.006 | минимальная длительность события |
| `n_samples` | отсчёты | `N_SAMPLES_GAZE_SHIFT` = 3 | минимум отсчётов на событие (для модели порогов); саккаде нужно 4, переводу взора 3 |
| `min_fixation_duration_s` | с | 0.050 | минимальная длительность фиксации |
| `min_subprocess_duration_s` | с | `= min_event_duration_s` | минимум подпроцесса при разбиении |
| `max_merge_gap_s` | с | `= min_event_duration_s/2` | разрыв при склейке фиксаций |
| `trend_alpha` | — | 0.05 | уровень значимости критерия тренда |
| `trend_slope_min` | град/с | `= fixation_velocity_limit_deg_s` | минимальный значимый наклон |
| `spread_measure` | — | `"std"` | режим разброса: `std`, `p95`, `peak` |
| `spread_limit_deg` | град | из модели | допустимый разброс фиксации |
| `drop_invalid_spread` | — | `False` | отбрасывать фиксации по разбросу |
| `drop_short_fixations` | — | `True` | отбрасывать короткие фиксации |
| `trim_fixations_by_velocity` | — | `True` | урезать фиксацию до отсчётов со скоростью ниже порога |
| `fixation_velocity_window_s` | с | 0.010 | окно скорости для этого критерия: `abs(Δp) / w`; при заданном `col_speed` не используется |
| `homogeneity_split` | — | `True` | требовать постоянства положения: дробить неоднородный интервал |
| `split_alpha` | — | 0.01 | уровень значимости тестов однородности |
| `split_min_points` | отсчёты | 5 | минимум отсчётов в половине при разбиении |
| `split_score_min_with_pvalue` | — | 1.0 | мера различия при значимом p; больше = слабее требование |
| `split_score_min_alone` | — | 2.5 | мера различия, достаточная сама по себе |

**Возвращает** `ScalarMarkup`: `angle_deg`, `speed_deg_s`, `gaze_shifts`, `fixations`, `fs_hz`, `span_s`, `params_used`; метод `.summary()` даёт интегральные характеристики записи (`describe_markup`).

### Анализ данных движения глаза: `mark_eye_data_with_full_angle_from_angles` и `mark_eye_rest_from_angles`

Обе принимают углы `yaw/pitch` глаза (в системе головы) и возвращают `(alpha_deg, саккады, таблица_интервалов)`. Ни одна не даёт фиксаций: фиксация — состояние взора относительно неподвижного пространства, а здесь углы заданы относительно головы. Отличие между функциями одно:

| функция | третья таблица | проверка скорости |
|---|---|---|
| `mark_eye_data_with_full_angle_from_angles` | интервалы между саккадами | нет |
| `mark_eye_rest_from_angles` | интервалы покоя | да: интервал урезан до отсчётов ниже порога |

Пороги выводятся из частоты записи, как и везде: `min_peak_velocity_deg_s`, `rest_velocity_limit_deg_s` и `min_amplitude_deg` по умолчанию `None`, то есть «взять из модели». Порог скорости здесь называется иначе, чем при анализе данных движения взора: он отделяет **покой глаза**, а не фиксацию, поэтому параметр расщеплён надвое — у взора остался `fixation_velocity_limit_deg_s`, где термин верен. Прежнее имя поднимает `NotImplementedError` с указанием замены; значение и поведение параметра не изменились. Событие здесь — **саккада**, поэтому модель берётся при `N_SAMPLES_SACCADE = 4`, в отличие от разметки взора с `N_SAMPLES_GAZE_SHIFT = 3`. С 222 Гц оба значения дают одно и то же: связывают физиологические пределы.

### `stable_intervals_by_velocity(data, *, col_horizontal, col_vertical, col_time="T_s", velocity_limit_deg_s, min_points=3, ...)`

Устойчивые интервалы: подряд идущие отсчёты, на которых скорость не выше порога. События не используются, интервал не дробится и не склеивается. Скорость — угол большого круга между соседними отсчётами, делённый на фактическую длину шага. Возвращает границы, длительность, число отсчётов, средние координаты, наклоны МНК и их p-value.

### `mark_gaze_events_direction(data, *, col_horizontal, col_vertical, col_forward=None, geometry="angles", ...) -> DirectionMarkup`

Запись направления взора: x-y или x-y-z. Три параметризации приводятся к одному расчёту, поэтому результаты сопоставимы между собой.

| `geometry` | Что во входных столбцах | Дополнительно |
|---|---|---|
| `"angles"` | yaw / pitch | `deg=True` — в градусах; нейтраль (0, 0) |
| `"plane"` | координаты точки на плоскости | **`r` обязателен** — расстояние от центра вращения до плоскости, в тех же **метрических** единицах, что координаты (мм, см, м; не пиксели); `horizontal_neutral`, `vertical_neutral`, `k` |
| `"vector"` | компоненты вектора направления | нейтраль = медианное направление записи |

Считаются: `eccentricity_deg` (угол до нейтрального направления), `azimuth_deg` (направление отклонения), `speed_deg_s` — **полная** угловая скорость (модуль производной единичного вектора: видит и радиальное, и тангенциальное движение), амплитуда события — угол большого круга.

Остальные параметры — как у `mark_gaze_events_1d`.

**Возвращает** `DirectionMarkup`: `eccentricity_deg`, `azimuth_deg`, `speed_deg_s`, `gaze_shifts`, `fixations`, `fs_hz`, `neutral_direction`, `span_s`, `params_used`; метод `.summary()` даёт интегральные характеристики записи (`describe_markup`).

| `mean_event_duration_s` | с | средняя длительность события |
| `n_intervals`, `intervals_total_duration_s` | шт., с | число фиксаций и их суммарная длительность |

Вызов: `res.summary()` для результата разметки взора либо `describe_markup(events=..., intervals=..., span_s=...)` при анализе данных движения глаза, где возвращается не объект, а тройка. Заданные явно таблицы важнее взятых из `markup`.

## `models` — физиологические модели

### `min_saccade_minima_by_sampling(fs_hz, n_samples=N_SAMPLES_SACCADE, ...) -> MinDetectableSaccade`

Граница разрешающей способности записи и все пороги разметки.

```
a_min   = max( (1000·n_samples/fs / T0)^(1/m),  v_идеал · t_фикс_мин )
t_min   = T0 · a_min^m
v_peak  = V0 · a_min^n
v_фикс  = max( a_min / max(t_min, t_фикс_мин),  v_идеал )
разброс = max( a_min, разброс_идеал )
```

Физиологические пределы (`IDEAL_FIXATION_VELOCITY_DEG_S = 5` град/с, `IDEAL_FIXATION_SPREAD_DEG = 5` град, `MIN_FIXATION_DURATION_S = 0.050` с) не дают модели давать бессмысленные значения при высоких частотах. Все они объявлены в модуле `constants` — см. раздел ниже.

Поля: `a_min_deg`, `t_min_s`, `v_peak_deg_s`, `v_fixation_deg_s`, `t_fixation_s`, `spread_max_deg`, `a_min_by_model_deg`, `a_min_at_floor`, `v_fixation_by_model_deg_s`, `v_fixation_at_floor`, `model`.

### `approx_params_by_fs(fs_hz) -> PowerDurationModel`

Параметры главной последовательности `(T0_ms, m, V0, n)` — таблица 4 статьи [Kruchinina A., Xu X. Analysis of saccadic main sequence relationship from a time-optimal control perspective // Russian Journal of Biomechanics. — 2026. — Vol. 30, no. 1. — P. 108–114](https://doi.org/10.15593/RJBiomech/2026.1.10) с кусочно-логарифмической интерполяцией по частоте. Табличные константы остаются в миллисекундах, как в публикации.

### `max_increment_deg(fs_hz, v_max=MAX_EYE_VELOCITY_DEG_S) -> float`

Максимальное допустимое приращение координат за кадр, град.

## `constants` — заданные константы

Одно объявление на величину: значение, встречающееся больше чем в одном месте, объявлено здесь и импортируется всеми модулями. Значения, встречающиеся ровно один раз, остаются в сигнатуре своей функции.

| Группа | Константы |
|---|---|
| физиология глаза | `EYE_RADIUS_MM` = 12.0 мм, `MAX_EYE_VELOCITY_DEG_S` = 900 град/с, `IDEAL_FIXATION_VELOCITY_DEG_S` = 5 град/с, `IDEAL_FIXATION_SPREAD_DEG` = 5 град, `MIN_FIXATION_DURATION_S` = 0.050 с |
| требования к записи | `N_SAMPLES_SACCADE` = 4, `N_SAMPLES_GAZE_SHIFT` = 3 |
| значения по умолчанию | `DEFAULT_MIN_EVENT_DURATION_S` = 0.006 с, `DEFAULT_MAX_AXIS_DT_S` = 0.006 с, `DEFAULT_FIXATION_VELOCITY_WINDOW_S` = 0.010 с, `DEFAULT_TREND_ALPHA` = 0.05, `DEFAULT_BCEA_PROBABILITY` = 0.90, `DEFAULT_MIN_BLINK_GAP_S` = 0.050 с, `DEFAULT_REFINE_SEARCH_S` = 0.100 с |

## `for_raw_data` — сырые данные глаза

Метрический вход, то есть положение зрачка в линейных единицах, — не основной: по умолчанию координаты взора и глаза задаются углами в градусах. Порядок здесь такой: **миллиметры → перевод в углы (`make_okulogram`) → дальше стандартная разметка**, теми же функциями и с теми же порогами. Единицы координат зрачка — **миллиметры**: они связаны радиусом `EYE_RADIUS_MM` = 12.0 мм, через который считается угол. Измерения в пикселях и метрах библиотека не принимает.

Для приборов вроде **Vive Pro Eye**, дающих положение каждого глаза отдельно, эти функции применяются к каждому глазу **по отдельности**: сглаживание → своя нейтраль → свои углы. Усреднять координаты глаз до перевода в углы нельзя: межзрачковое расстояние вошло бы в результат постоянным смещением.

| Функция | Что делает |
|---|---|
| `make_okulogram(eye_coord, neutral=None, r_eye=EYE_RADIUS_MM)` | **мм** → градусы: `atan2(eye_coord − neutral, r_eye)`; `r_eye` — физиологическая константа `EYE_RADIUS_MM` = 12.0 мм. Другие единицы сюда подавать нельзя: библиотека не предназначена для измерений в пикселях или метрах (см. «Принятые допущения» в `Sci_base-rus.md`) |
| `find_central_position(eye_x, eye_y, eye_z=None)` | нейтральное положение = медиана по каждой координате |
| `star_eye_smoothing(eye_coord, t_s, max_velocity, eps, ...)` | медианный фильтр, не размывающий быстрые движения; порог `max_velocity · dt`; невалидные отсчёты → **NaN** |
| `smooth_eye_position_mm(eye_x, eye_y, t_s, max_velocity, eps, eye_z=None, ...)` | то же покоординатно, координаты в **мм**, длина результата N (у `star_eye_smoothing` — N−2) |
| `angular_velocity_at_rate(t_s, horizontal, vertical, fs_hz=None) -> VelocityResult` | скорость; модуль — угол большого круга за шаг, `v_x`/`v_y` — производные координат; `fs_hz=None` — частота записи, задана — децимация |

### `bcea_deg2(horizontal, vertical, *, probability=0.90) -> float`

Площадь эллипса рассеяния взора, град². Мера разброса, дополняющая `spread_*`: те дают радиус облака, эта — площадь заметаемой области, поэтому чувствительна к вытянутости и наклону облака.

```
BCEA = 2 · k · π · √(det Cov),   k = −ln(1 − probability)
```

Ковариация несмещённая (`ddof=1`). Меньше трёх валидных точек — `NaN`, вырожденное облако (точки на прямой) — `0`. Мера перенесена из работы [Kruchinina A. P., Polikanova I. S. Analysis of Eye and Head Tracking Movements during Shooting from the Prone Position in Biathletes Compared to Novices // Psychology. Journal of the Higher School of Economics. — 2025. — Vol. 22, no. 3. — P. 473–488](https://doi.org/10.17323/1813-8918-2025-3-473-488), где так считалась площадь области прицеливания при стрельбе биатлонистов.

Та же величина попадает в таблицу фиксаций колонкой `bcea_deg2` — **только в `mark_gaze_events_direction`**: площадь имеет смысл как проекция на неподвижное пространство, а у движения глаза относительно головы такой проекции нет.

### `convex_hull_area_deg2(horizontal, vertical) -> float`

Площадь выпуклой оболочки облака точек взора, град². Вторая мера площади рядом с `bcea_deg2`, и смысл у них разный: эллипс — модельная область заданной плотности, оболочка — граница фактически посещённых точек. Эллипс устойчив к одиночному выбросу, но предполагает нормальность; оболочка ничего не предполагает, но выбросом раздувается.

Расхождение мер информативно: оболочка много больше эллипса означает выбросы либо облако, далёкое от нормального.

Меньше трёх валидных точек — `NaN`; точки на одной прямой — `0`. В таблице фиксаций — колонка `hull_area_deg2`, там же, где `bcea_deg2`.

### `BilinearRegression(threshold=0.5)`

Кусочно-линейная регрессия: ломаная из двух отрезков, применяется к распределению интервалов в осях `ln(Δt)` — `ln(f(Δt))`. Два наклона и есть величины, по которым оценивается показатель Хёрста; как наклон переводится в показатель, зависит от способа построения оси и остаётся за вызывающим.

| Метод | Что делает |
|---|---|
| `fit(X, Y, *, plot=False) -> BilinearFit` | подгонка и показатели; без `plot=True` ничего не рисует |
| `plot_fit()` | точки и два отрезка; требует extra `viz` |
| `predict(X=None, n_break=None)` | значения ломаной; без аргументов — на данных последней подгонки |
| `get_der()` | пара наклонов; оставлен ради прежнего кода, см. `BilinearFit.slopes` |

`X` должен быть отсортирован по возрастанию: излом ищется по индексу, а не по абсциссе. Отсчёты с `NaN` или `inf` в `Y` отбрасываются, как и первый отсчёт.

**`threshold` — это положение излома** как доля от размаха `X`, и подгонкой оно **не уточняется**: минимизация подбирает только три параметра прямых `(a_0, a_1, b_0)`. Поэтому значение по умолчанию 0.5 ставит излом в середину размаха `X` независимо от того, где данные ломаются на самом деле.

`BilinearFit`: `slope_left`, `slope_right`, `slopes`, `intercept`, `break_x`, `break_index`, `n_left`, `n_right`, `n_valid`, `r2`, `rmse`, `r2_single_line`, `params_used`. Сравнение `r2` с `r2_single_line` — те же данные, приближённые одной прямой — показывает, оправдан ли излом вообще.

Прежнее имя `biline_regression` продолжает работать как алиас.

## `orientation` — ориентация головы и взора

Кватернион — способ записи ориентации, а не понятие методики, поэтому наружу он не выходит: функции принимают таблицы и массивы, возвращают **градусы**.

**Зачем это в библиотеке про глаза.** Взор складывается из направления глаза относительно головы и ориентации головы в неподвижном пространстве. Прибор даёт первое углами, а второе — кватернионом или строкой `"(x,y,z)"`, и в разметку такой вид не годится. Функции этого модуля — переходник между записью прибора и величинами методики. Само сложение головы с глазом библиотека не делает: оно зависит от того, как прибор задаёт обе величины; разметка принимает уже готовый взор, а если положение головы не учтено, размечается движение глаза.

**Какая ось какому движению отвечает.** Система правая, ось X смотрит вперёд; та же система используется разметкой направления (`geometry="angles"`):

| Ось | Поворот вокруг неё | Движение взора | Азимут в разметке |
|---|---|---|---|
| **Z**, вертикальная | `yaw` | горизонтальное: влево/вправо | 0° при `yaw > 0`, 180° при `yaw < 0` |
| **Y**, поперечная | `pitch` | вертикальное: вверх/вниз | +90° вверх, −90° вниз |
| **X**, продольная («вперёд») | `roll` | торсия: наклон головы к плечу или циклоторсия глаза | направление взора не меняется, методика такое движение не размечает |

| Функция | Что делает |
|---|---|
| `angles_from_orientation(data, *, cols, axis_order, to_degrees)` | кватернионы → `roll_deg`, `pitch_deg`, `yaw_deg`; входные кватернионы нормируются |
| `angular_distance_deg(data, other, ...)` | кратчайший угол между двумя последовательностями ориентаций, град |
| `rotate_points(points, data, ...)` | поворот векторов заданной ориентацией; принимает `[N,3]` или `[3]` |
| `quaternion_from_matrix_angles_deg(rows)` | матрица поворота 3×3 → углы в градусах |
| `parse_vector_column(values, axis_order)` | разбор столбца строк `"(x,y,z)"` → массив `[N,3]` |

`cols` — имена столбцов в порядке `(x, y, z, w)`, по умолчанию `("q_x", "q_y", "q_z", "q_w")`. `axis_order` — `"xyz"` либо `"xzy"`: приборы расходятся в наименовании осей (у одних вверх смотрит Z, у других Y), поэтому достаточно перестановки компонент. Переходом между левой и правой тройками координат это не является — тот требует ещё смены знака; записи в левой тройке приводятся к правой до вызова.

Все четыре функции сверены со `scipy.spatial.transform`: расхождение не выше 1e-9 на 200–500 случайных поворотах.

## Что ещё не приведено в порядок

> Раздел только в русской версии: это заметки по внутреннему состоянию кода, а не описание API. В английском справочнике его нет.

Пакет устанавливается: есть `pyproject.toml`, `__init__.py` и `__all__` (99 имён), публичная граница зафиксирована — прежний пункт снят.

Осталось:

* **Излом в `BilinearRegression` не подбирается.** `minimize` оптимизирует только три параметра прямых, а положение излома берётся из `threshold` и не меняется, поэтому по умолчанию он оказывается в середине размаха `X` независимо от данных. Для оценки Хёрста это существенно: наклоны считаются относительно точки, которая выбрана не по данным. Подбор излома изменил бы численные результаты и требует решения автора методики (см. `r2` против `r2_single_line` как способ увидеть проблему на конкретной записи).

## `saccade_model` — модель траектории саккады

Глаз описан звеном второго порядка с релейным управлением: разгон, реверс, торможение и два момента переключения, которые находятся из условия попадания (к концу движения угол равен амплитуде, скорость — нулю). Решение безразмерно, под конкретную саккаду масштабируется амплитудой и длительностью.

| `switch_times(model, *, y0=0.7)` | моменты переключения, безразмерные |
| `trajectory(model, *, switch=None, dt=0.001)` | безразмерные угол, скорость, управление |
| `saccade_template(amplitude_deg, duration_s, *, fs_hz=1000, model=None)` | одна кривая: `t_s`, `angle_deg`, `speed_deg_s` |
